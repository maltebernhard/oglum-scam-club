# OSC

A React Native (Expo) mobile app that generates check-in style screenshots/clips by overlaying
a name, location, activity and timestamp onto a template video (USC mode) or template image
(WellPass mode). The user fills in a form, picks or reuses a saved template, and the app renders
the overlay in real time and lets them export a photo/video.

- **Framework:** [Expo](https://expo.dev) SDK 54 (React Native 0.81, React 19)
- **Entry point:** [index.js](index.js) → [App.js](App.js)
- **Platforms:** Android (native project checked into `android/`), iOS (not yet prebuilt), Web (via `expo start --web`)
- **Key libraries:** `expo-video`, `expo-image-picker`, `expo-file-system`, `@react-native-async-storage/async-storage`

## Setup

```bash
git clone <this-repo-url>
cd OSC
npm install
```

## Running in development

The fastest way to iterate is Expo's dev server with Expo Go or a custom dev client:

```bash
npx expo start
```

Then either:
- Press `a` to open on a connected Android device/emulator, `w` for web, or scan the QR code with
  the Expo Go app on a physical device.
- Run `npm run android` to build and launch the native Android app directly (requires the Android
  SDK to be installed and configured, see below).
- Run `npm run ios` on macOS to build and launch the native iOS app (requires Xcode; the `ios/`
  native project is not checked in and will be generated on first run via `expo prebuild`).

## Building the Android app locally

The native Android project is already checked into `android/` (this is an Expo "prebuilt"
project, not a bare managed one), so no `expo prebuild` step is required to get started.

1. Install Android Studio and, through its SDK Manager, an Android SDK platform + build tools
   matching the versions used by this project (Android Studio will prompt you if anything is
   missing when you open the `android/` folder).
2. Create `android/local.properties` (this file is machine-specific and git-ignored) pointing at
   your SDK install:
   ```properties
   sdk.dir=/absolute/path/to/your/Android/Sdk
   ```
3. Build and install a debug build onto a connected device/emulator:
   ```bash
   npm run android
   # or, from the android/ folder:
   ./gradlew assembleDebug
   ```
   The debug build is signed with the checked-in `android/app/debug.keystore`, which is a
   non-secret, shared debug key (standard practice for React Native projects) — it is **not** used
   for release signing.

You can also simply open the `android/` folder directly in Android Studio and run it from there.

## Cloud builds (EAS)

Build configuration lives in [eas.json](eas.json). With the [EAS CLI](https://docs.expo.dev/eas/)
installed and logged into the appropriate Expo account:

```bash
eas build -p android --profile preview    # internal-distribution APK/AAB for testing
eas build -p android --profile production # production APK (see eas.json for build type)
```

## Project structure

```
App.js            # Main app component and all screen/UI logic
app.json          # Expo app config (name, bundle identifiers, icons, plugins)
eas.json          # EAS Build profiles
assets/           # App icons, splash images, and template video/image used for overlays
android/          # Checked-in native Android project (generated by `expo prebuild`, then customized)
```

## What's not committed

The `.gitignore` excludes everything that is generated or installed rather than authored,
including:
- `node_modules/` (installed via `npm install`)
- `.expo/`, `dist/`, `web-build/` (Expo/Metro build & cache output)
- `android/build/`, `android/app/build/`, `android/.gradle/`, `android/.kotlin/` (Gradle build output)
- `android/local.properties` (machine-specific Android SDK path)
- `.idea/` (JetBrains IDE project files)
- A handful of unreferenced leftover design assets (e.g. `assets/Wellpass.xcf`) that aren't used
  by the app and aren't needed to build or run it.

If you regenerate the native projects with `expo prebuild`, review the diff before committing —
this repo intentionally keeps a customized `android/` project rather than relying on prebuild
running automatically on every install.
